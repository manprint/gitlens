Intent: Settings is a tabbed page where everything that can safely be configured from the console is configurable — console preferences, data retention (with preview and confirmation), advisor rule enablement and observation windows, notification channels (status and test; write-only secrets after Q2), names — and everything else is listed with its reason.
Prerequisites: 9.1 (table controls), 10 (names panel), 17.1 (captions) — see execution order.

API: `GET /api/v1/settings/retention` (`getRetention`) → `[{family, hypertable, days, source: 'default'|'custom', min_days, max_days: 365}]` where `min_days = max(3, ceil(compress_after_days) + 1)` per family (compression policies: 48 h → 3 days; `metrics_bloat` 7 d → 8 days; S0 reads the live `policy_compression` config and the value is computed, not hard-coded, so retention never drops below the compression horizon); `GET /api/v1/settings/retention/preview?family=&days=` (`previewRetention`) → `{family, days, chunks_to_drop, bytes_to_free, oldest_chunk_at, newest_dropped_chunk_end}` from `show_chunks(hypertable, older_than => $days * interval '1 day')` + `chunks_detailed_size`; `PUT /api/v1/settings/retention/{family}` (`setRetention`) body `{days, confirm}` → `remove_retention_policy(hypertable, if_exists => true)` then `add_retention_policy(hypertable, drop_after => make_interval(days => $2))` in one transaction; shortening (new days < current) without `confirm: true` → 409 `{error:'confirmation required', preview}`; lengthening needs no confirmation; `days` outside [`min_days` of that family, 365] → 400; unknown family → 404; storage unavailable → 503. Deletion happens at the next policy run (documented in the UI). Everything parameterised; family → hypertable by whitelist (I-3).
- D18 advisor: table `advisor_rule_overrides(tenant_id text, rule_id text, enabled boolean not null, updated_at timestamptz not null default now(), primary key (tenant_id, rule_id))`; `GET /api/v1/advisor/rules` (existing) gains `enabled` (default true) and `overridden`; `PUT /api/v1/advisor/rules/{id}/override` (`setAdvisorRuleOverride`) body `{enabled}`, 404 unknown rule; the engine skips disabled rules and resolves their open findings with reason `rule_disabled` at the next evaluation (re-enabling re-opens naturally). Thresholds are not editable (the engine exposes none). Observation windows (D22c): table `server_settings(tenant_id text, key text, value jsonb not null, updated_at timestamptz not null default now(), primary key (tenant_id, key))`; keys `window.unused_index` and `window.backup_history` only (seconds, 3600–7776000; any other `window.*` key → 400, D22); `GET/PUT /api/v1/settings/advisor-windows` (`getAdvisorWindows`, `setAdvisorWindows`); `docs`: short windows raise false positives (UI warning).
- D18 notifications (split by Q2): **11.5a** `GET /api/v1/notification-channels` (`getNotificationChannels`) → `[{kind: 'slack'|'webhook'|'google_chat', configured, source: 'env', host}]` (hostname only; never the URL) and `POST /api/v1/notification-channels/{kind}/test` (`testNotificationChannel`) sending a clearly labelled message "pglens test notification" → `{delivered, status, error?}` (error passed through `redactError`); **11.5b (BLOCKED on Q2)** `PUT/DELETE /api/v1/notification-channels/{kind}` write-only URL storage in `notification_channels` with DB value overriding the environment, validation `https://` (or `http://` only for loopback/private hosts), ≤ 2048 chars, never returned/logged (I-10).
- Preferences (client, `web/src/lib/preferences.ts`, best-effort storage, never throws): `theme`, `defaultTimeRange` (`1h|6h|24h|7d`), `refreshInterval` (`auto|off|15s|30s|60s`; `auto` = today's per-surface policy; a chosen value overrides only surfaces with interval ≥ 15 s and scales their `staleAfter`, `off` sets it to 0; `command`, `locks`, `activity`, `static` keep their policy — R-11.0 P1), `tablePageSize` (20|50|100, D23). Read back after reload (I-11); the pages' defaults honour them (time range hook default, query refetch interval, table page size).
- Tabs: `/settings?tab=inventory|preferences|retention|advisor|notifications|names|audit` (default `inventory`; existing sections `ServerInfo`, `InventoryTables`, `CommandAudit` move into tabs without behaviour change; existing tests keep their IDs, I-7).
