Intent: the Instance Overview has summary tiles, a clearly separated chart area organised in semantic groups, and new charts about queries, tables and indexes.
Prerequisites: 1 (chart foundation; needed from 3.2, not by 3.1), 2.3 (Host charts linked from the nav).
Phase closure: P3; review by `advisor`.

## Local design context
Plan revision: 1.
- D4 (layout), D5 (`workload/series` contract), D1 (steps), I-3 (whitelist SQL), I-6.
- Tables (from `internal/store/migrations/0002/0007/0014`): `metrics_statements(ts, tenant_id, cluster_id, instance_id, datname, queryid, calls_rate, exec_time_rate_ms, rows_rate, shared_blks_hit_rate, shared_blks_read_rate, wal_bytes_rate, sample_seconds, temp_blks_written_rate)`; `metrics_tables(ts, tenant_id, cluster_id, instance_id, datname, schemaname, relname, seq_scan, seq_tup_read, idx_scan, idx_tup_fetch, n_tup_ins, n_tup_upd, n_tup_del, n_tup_hot_upd, n_live_tup, n_dead_tup, …, autovacuum_count, autoanalyze_count, relpages, reltuples, total_bytes, table_bytes, toast_bytes)` where the double-precision counters are stored as per-second rates (same convention as the `/tables` API fields `*_rate`); `metrics_indexes(ts, …, indexrelname, idx_scan, idx_tup_read, idx_tup_fetch, idx_blks_read, idx_blks_hit, index_bytes, is_valid, …)` (rates for the counters, `index_bytes` a gauge). Lookup indexes exist on `(instance_id, datname, ts DESC)`.
- Series whitelist (D5), name → SQL expression over rows of one scrape, then averaged per bucket:
  statements: `calls`=`sum(calls_rate)` (calls/s), `exec_time`=`sum(exec_time_rate_ms)` (ms of execution per second), `rows`=`sum(rows_rate)`, `blks_hit`=`sum(shared_blks_hit_rate)`, `blks_read`=`sum(shared_blks_read_rate)`, `hit_ratio`=`sum(hit)/nullif(sum(hit)+sum(read),0)`, `wal_bytes`=`sum(wal_bytes_rate)`, `temp_blks`=`sum(temp_blks_written_rate)`;
  tables: `seq_scans`=`sum(seq_scan)`, `idx_scans`=`sum(idx_scan)`, `tup_ins`, `tup_upd`, `tup_del`, `tup_hot_upd` (sums of the stored rates), `dead_tuples`=`sum(n_dead_tup)` (gauge), `live_tuples`=`sum(n_live_tup)` (gauge), `autovacuums`=`sum(autovacuum_count)`;
  indexes: `idx_scans`=`sum(idx_scan)`, `idx_tup_read`, `idx_tup_fetch`, `idx_blks_read`, `idx_blks_hit`, `index_bytes`=`sum(index_bytes)` (gauge).
  Bucket: `time_bucket(make_interval(secs => $step), ts)`; inner level groups by exact `ts` (one scrape), outer averages the per-scrape sums. `kind` (`rate|gauge`) is part of each series' response so the UI picks the step with `stepFor`. Counts are over the **tracked** rows (agent `top_n`), the cards say "tracked statements/tables/indexes".
- Overview groups and charts (D4): **Workload** — Transactions per second (commits, rollbacks: `pg_xact_commit_total`, `pg_xact_rollback_total`, wide), Connections (`pg_connections_used`, `pg_connections_limit`), Deadlocks and conflicts (`pg_deadlocks_total`, `pg_conflicts_total`); **Memory & I/O** — Cache hit ratio (`pg_blks_hit_ratio`), Blocks read vs hit (`pg_blks_read_total`, `pg_blks_hit_total`), Temp files and bytes (`pg_temp_files_total`, `pg_temp_bytes_total`); **WAL & checkpoints** — WAL generation (`pg_wal_wal_bytes`, `pg_wal_wal_records`, `pg_wal_wal_fpi`), Checkpoints (`pg_checkpoints_timed_total`, `pg_checkpoints_requested_total`), Checkpoint write/sync time; **Queries** — Calls per second (statements `calls`), Execution time per second (`exec_time`), Rows per second (`rows`), Statement block reads (`blks_read`), Statement temp blocks (`temp_blks`); **Tables & indexes** — Sequential vs index scans (tables `seq_scans`, `idx_scans`), Tuple churn (`tup_ins`, `tup_upd`, `tup_hot_upd`, `tup_del`), Dead tuples (`dead_tuples`), Index scans (indexes `idx_scans`), Index size (`index_bytes`). Names of existing `pg_*` metrics that do not exist for the instance (older PG) render the card's empty state, never an error banner.
