Plan revision: 1.
- D12 (filter-before-table, URL state per table prefix), D13 (sort buttons), D23 (pagination), I-9, I-12.
- Existing: `web/src/components/layout/DataTable.tsx` (TanStack v9 style: `useTable({features, columns, data})`, `rowSortingFeature`, `columnVisibilityFeature`, virtualization above 200 rows, footer "Showing N of M scope" with `Truncated`), 21 usages (`DriftSection`, `SlotsSection`, `RuleCatalogue`, `CatalogSection` ×8, `InternalsSection` ×4, `LogicalReplicationSection` ×2, `QueryListPage`, `InventoryTables` ×3); bespoke tables in `RulesPage`, `SilencesPage`, `TopologyGraph` ("Replication topology edges"), `RelationsSection` (737 lines), `SettingsSection`, `PlanHistory`, `CommandAudit`, `IndexAnalysisPage` (+ `CleanupPanel`, `DeadRowsPanel`, local `SortHeader.tsx`); the pure sorters already in the new libs `deadRows.ts` (`compareDeadRows`), `indexAnalysis.ts`, `indexCleanup.ts`. Nothing outside `DataTable` paginates today. Two different pages show statements: the **Slowest queries** page is `web/src/features/queries/SlowQueriesPage.tsx` (route `/queries`, ranked `<ol aria-label="Slowest queries">` of cards, `SLOWEST_LIMIT = 20`, no table, pager, search or sort) and `QueryListPage` is the per-instance **Query inspector** (route `/instances/:instanceId/queries`, title "Query inspector", already a `DataTable`). This plan paginates both, each on its own route; every test and e2e step names the route.
- `lib/tableControls.ts` API (pure): `compareValues(a, b, dir)` (null/undefined/NaN last in both directions; numbers numeric; strings `localeCompare` with `numeric: true, sensitivity: 'base'`; booleans false < true; stable via original index tiebreak in `sortRows`), `sortRows(rows, key, dir, accessors)`, `matchesSearch(row, q, fields)` (case-insensitive substring on any of the fields, trims, empty q = true), `FilterSpec<T> = {id, label, kind: 'select'|'multi'|'min', options?, accessor, predicate?}`, `applyFilters(rows, specs, values)`, `paginate(rows, page, pageSize)` → `{rows, page (clamped), pageCount, from, to, total}`, `PAGE_SIZES = [20, 50, 100]`, `DEFAULT_PAGE_SIZE = 20`.
- `useTableState(prefix, defaults)` (hook, `web/src/hooks/useTableState.ts`): reads/writes `<prefix>.q`, `.sort`, `.dir` (`asc|desc`), `.page`, `.size`, `.f.<id>` in `useSearchParams` with `replace: true`; unknown values fall back to defaults; any change other than `page` resets `page` to 1; returns `{state, set, clear, activeFilterCount}`.
- Filter rules by table (D12 rule set, applied per table in 9.2/9.3 and recorded in `tables-inventory.md`): identity search always; selects for columns named state/status/kind/role/severity/type/scope/database/schema/source/method; `min` for size/calls/dead tuples where the page already sorts by it. The first step of 9.2 produces `docs/plans/005_plan-ConsoleInsights/tables-inventory.md` listing each table (file, ariaLabel/heading, columns, default sort, search fields, filters, notes); the `advisor` approves that file before the 21 integrations start (it is the design contract; the worker does not invent filters). A table whose page already has a control for that column (`CatalogSection` and `InstancePage` Database selects, `SlowQueriesPage` Server/Database selects) gets no duplicate filter; filter labels are table-scoped (`Filter <table> by <column>`); no new control may share an accessible name with an existing one on the same page (`CatalogSection.test.tsx` ~242/248, `InstancePage.test.tsx` ~210/247 and `SlowQueriesPage.test.tsx` ~95 stay unchanged).
