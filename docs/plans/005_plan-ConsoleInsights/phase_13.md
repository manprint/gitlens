# Phase 12 — Full search (Slowest queries, Index analysis, Findings)

Intent: typing in the search box finds every matching query, index, table, column and finding that pglens has collected in the selected range — not only the rows on screen.
Prerequisites: 9.1 (shared table controls and URL state).
Phase closure: P12; review by `advisor`.

## State and ownership contract
Read STATE.md §0–1 first. Open before edits; checkpoint at a recovery boundary; close with evidence. Missing design goes to the `advisor`.

## Local design context
Plan revision: 1.
- D20 (all matching rules and endpoints), D12 (client table search stays for other pages), I-3 (user input never reaches SQL text), I-9 (truthful counts), I-1 not applicable.
- Matching: `searchPattern(q string) (pattern string, err error)`: trim; reject length < 2 or > 200 (`ErrSearchTooShort`/`ErrSearchTooLong` → HTTP 400 `q must be 2–200 characters`); escape `\`, `%`, `_` with a backslash; return `"%" + escaped + "%"`; SQL uses `col ILIKE $n ESCAPE '\'`. `queryid` is compared as `queryid::text ILIKE $n`.
- Existing handlers to extend: `handleStatements` (`internal/server/api.go` ~lines 1141–1365; params `instance_id`, `database`, `from`, `to`, `order_by`, `limit` default 20 max 1000; statement rows joined to `query_texts(query_text, queryid, datname, cluster_id)`); `getFindings` handler (locate with `tokensave_search`; table `findings`: `rule_id,title,detail,remediation,object_name,datname,mute_reason,evidence jsonb`; limit default 100 max 1000, ordered open/degraded first). Index and table facts: `object_facts(kind,key,labels,value_text,value_json)`; kinds used by the indexes API and `table_columns`; column inventory fact `table_columns` (ValueJSON array of `{name, type, …}`), statements/tables/indexes metrics tables `metrics_statements`, `metrics_tables`, `metrics_indexes`.
- Result shape for `searchInstance`: group order statements, indexes, tables, columns; `link` is a relative app path (`/queries?instance=…&q=…` (the `instance` parameter `SlowQueriesPage` reads), `/indexes?instance=…&tab=indexes&focus=<key>`, `/indexes?…&tab=dead-rows&focus=…`); snippets are produced server-side as `[ {text, match:boolean} … ]` around the first match (<= 160 chars, `…` at cuts) so the client only renders.
- UI: shared `SearchBox` (debounce 300 ms, min 2 chars, `?q=`, clear button, `role="search"`, busy state) and pure `highlightMatches(text, q)` → `{text, match}[]` (case-insensitive, non-overlapping, escapes nothing: React renders text nodes).
