# Phase 15 — Full HD fit: tables and pages sized for 1920×1080 without scrollbars

Intent: on a Full HD monitor with the browser full screen (1920×1080) or maximised (≈ 1920×950) every table page shows its toolbar, its default 20-row table and its pager without a page scrollbar and without a horizontal scrollbar; the layout is guarded by a route inventory so a new page cannot silently break it.
Prerequisites: 9 (shared table controls with pagination), 0.4 (Playwright harness; fit measurements run on the live stack). Order: 15.1, 15.2 and 15.3 right after phase 9; **15.4 runs after phase 16** (all pages final), so P15 closes after P16 (execution order in the overview).
Phase closure: P15; review by `advisor` with screenshots at 1920×1080 and 1920×950.

## Local design context
Plan revision: 1.
- D26 (overview) is the contract; assumption A2 (reference viewports 1920×1080 and 1920×950). Measured shell facts to start from (verify in 15.1 S1, they supersede the overview estimate): `AppShell` content column has `lg:pl-64` (sidebar 256 px), `max-w-[1600px]`, `py-6` (24 px top and bottom), a 56 px sticky header (`min-h-[calc(100vh-3.5rem)]`), `PageHeader` with a title and a description clamped to `max-w-3xl`.
- Budget method: the table card must fit in `viewport height − (header + page chrome)`. 15.1 S1 **measures** with Playwright on the live stack the real heights of: shell header, page header, tab bar, toolbar, table header, one row, pager, paddings, then fixes the density tokens so `chrome + 20 × row + pager ≤ 950 − 4` at 1600 px width and up. The measured numbers are written into `fullhd-inventory.md` and into the `D26` budget row via a plan revision if they differ by more than 8 px.
- Rules: density tokens `--table-row-h` (default 28 px at ≥ 1600 px, unchanged below), compact cell padding, table `table-layout: fixed` with per-column width hints (`meta.width` in the column defs), free-text columns single-line with ellipsis and the full text in a tooltip, expanding a row is a user action (never the resting state), the content area is full width from 1600 px (the `max-w-[1600px]` clamp is lifted to `max-w-none` from `min-[1600px]`), **one primary table per view** (a page that stacks several tables becomes tabs or collapsible sections each with its own table), page sizes 50/100 scroll **inside** the table card (sticky header), never the page. Pages with charts (Overview, ASH, Host, replication lag) are exempt from the vertical rule only (marked `charts` in the inventory) and never from the horizontal one.
- Route inventory: `web/e2e/fullhd_routes.ts` exports `FULLHD_ROUTES: {path, name, kind: 'fit'|'charts'|'exempt', reason?: string, pendingUnit?: string, setup?: …}[]`; a unit test (`FHD-ROUTES-001`) compares it with the router's route table (`web/src/routes/index.tsx`) so a new route not listed fails (I-13); every `exempt` carries a written reason; settings tabs and index-analysis tabs are separate entries whose `path` carries the query string (`/settings?tab=retention`); `FHD-ROUTES-001` compares only the pathname part with the router table — every router pathname has ≥ 1 entry, every entry's pathname exists in the router — and every tab value of the index-analysis tab list (`TABS` in `IndexAnalysisPage.tsx`, exported by 15.1) has its own entry; the Settings tab entries are added by 11.1, which extends this test with `SETTINGS_TABS` (15.1 runs earlier, so `/settings` has a single entry until then). `fullhd_routes.ts` is imported by vitest, so it holds data only (type-only imports from Playwright, no runtime import); `/login` and `*` are listed as `exempt` with the reason "no data page".
- Pages created or restructured by later units (10.2, 11.1, 12.2, 14.2, 16.3, 4.4, 5.1; 13.3 only adds a banner to an already registered route) add their route to `fullhd_routes.ts` and call `assertFits` for it in their own e2e test (I-13); 15.4 re-measures the final list.
- Responsive behaviour below 1600 px is unchanged (existing tests keep their IDs, I-7).
