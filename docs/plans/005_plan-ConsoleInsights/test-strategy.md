# Frontend test strategy — Playwright against the live stack

Authority: user request (REQ-41, 2026-10-29): use Playwright on the active instance we have; the stack may be taken down, updated and brought up again; Odoo may be stimulated with data to see that pglens indicators move correctly; the strategy must be accurate — no bugs.
Applies to every unit with a live e2e field. Harness built in 0.4; indicator/lifecycle suites in 6.4; gate IDs G-VIS / G-QA in STATE §3.

## 1. Layers (what proves what)

| Layer | Tool | Proves | Runs |
|-------|------|--------|------|
| Pure logic | vitest (`web/src/lib`) | formulas, formatters, classifiers | every unit |
| Component/contract | vitest + Testing Library + MSW, fixtures `web/src/test/fixtures/<operationId>.ts` | rendering, a11y (axe), URL state, API contract shape | every unit |
| Go unit/integration | `go test`, `-tags integration` (real PostgreSQL/TimescaleDB) | server/agent behaviour, SQL, ground-truth fixtures | every unit |
| **Live UI** | **Playwright against `http://127.0.0.1:9090` (the real stack, real browser)** | what the user sees: data present, indicators move with real stimulus, no console/network errors, layout (1920×1080), lifecycle resilience | unit closure (focused `-g`), phase closure, 6.2/6.4 |
| Human-eye review | screenshots + checklists C-* reviewed by the `advisor` | what assertions cannot see (legibility, overlap, balloon shapes) | phase closure |

No pixel-baseline comparison of live pages (live data is never identical): structure, numbers and canvas content are asserted; looks are reviewed from screenshots.

## 2. Environment and guard rails

- Stack: compose project `pglens-odoo` in `/home/agent/pglens-odoo-stack/` (Odoo 18, PostgreSQL 18, TimescaleDB for pglens, pglens-server, pglens-agent). UI `http://127.0.0.1:9090` (password in the stack `.env`, read by the harness; never logged), Odoo `http://127.0.0.1:9091` (admin/admin).
- Allowed without asking (dev stack only): rebuild images from the working tree, `docker compose up -d`, `stop/start/restart` of `pglens-server`, `pglens-agent`, `timescaledb` (the compose service name; the container is `pglens-odoo-timescaledb-1`), `odoo`, and `docker compose down` **without `-v`** limited to the services `odoo pglens-server pglens-agent timescaledb` (`down()` never stops `odoo-db`; the only drills that may stop or restart `odoo-db` are the 7.x HA drills and the explicitly listed exception LIFE-DOWN-UP-FULL, which needs a backup younger than 24 h). Forbidden: `down -v`, deleting volumes, any image pull except the digest-pinned base images of `Dockerfile.agent`/`Dockerfile.server` and the Odoo stack images that the authorised stack builds fetch, any network access beyond the local network and the already authorised build/webhook hosts.
- The harness refuses to run lifecycle tests unless `PGLENS_QA_ALLOW_LIFECYCLE=1`, the compose project is `pglens-odoo`, and a verified backup younger than 24 h exists in `/home/agent/odoo-backups/` (I-4): a directory whose `VERIFIED` file (written by `verify_backup.sh`; line 1 the backup's creation time, line 2 the sha256 of `SHA256SUMS`) has a creation time < 24 h old and a recorded hash equal to the current `sha256sum SHA256SUMS`. The guard only checks: units that need a backup (6.3, 7.x, 8.1, the lifecycle drills) take a fresh one with `backup.sh` (from the current leader via `DB_CONTAINER` after an HA switchover) and verify it first; stimulus tests need only `PGLENS_QA_ALLOW_STIMULUS=1`; a selection that contains any test that stops or restarts a service (all of `@lifecycle`, and in `@indicators` the RDY-E2E, SORIGIN-E2E-002/003 and IND-NOTIF tests) always runs with both flags.
- Stimulus objects live in schema `qa_tmp` and carry the tag `qa-<runid>` (`application_name`, table/row markers). A fixture finalizer removes them even after a failure; a final test (`QA-CLEAN-001`) asserts that `qa_tmp` is gone and no session with `application_name LIKE 'qa-%'` remains.

## 3. Harness (`web/e2e/qa/`, built in 0.4)

| Module | Purpose | Contract |
|--------|---------|----------|
| `stack.ts` | lifecycle (compose files: `compose.yml` plus the HA override `compose.ha.yml` when it exists, detected at start-up; service names are compose service names) | `stackStatus()`, `restart(service)`, `stop(service)`, `start(service)`, `down()`, `up()`, `rebuild()` (calls `/home/agent/pglens-odoo-stack/deploy.sh`: plain `docker build` of both images without `--pull`, then `compose up -d --no-deps --force-recreate pglens-server pglens-agent`), `waitReady(timeoutMs)` (polls `/readyz`, UI `/`, agent heartbeat/instance `last_seen` fresher than 45 s); every call logs to the test output with duration; no `sleep` — only polling with an explicit deadline |
| `pg.ts` | ground truth and stimulus on the monitored PostgreSQL via `docker exec pglens-odoo-odoo-db-1 psql -X -A -t` | `query(sql)`, `openSessions(n, {applicationName, idleInTransaction})` (held by one long-lived `psql` process each, killed in the finalizer), `lockPair(table, id)` (A holds a row lock, B waits), `burstWrites(n, rate)`, `slowQuery(ms, times)`, `cpuBurn(seconds)`, `deadRows(n)` (updates on `qa_tmp.t` with autovacuum disabled for that table), `deadlocks(count)` (two sessions `qa-deadlock-a`/`-b` update the rows of `qa_tmp.dl` in opposite orders until `pg_stat_database.deadlocks` grew by `count`; returns the measured increase), `truth.*` (`xactCommitTotal()`, `connections()`, `statementCalls(queryTextLike)`, `databaseSize()`, `deadTuples(table)`) |
| `odoo.ts` | application stimulus over JSON-RPC | `login()`, `createPartners(n)`, `writeOrders(n)`, `searchRead(model, domain)`, `browseLoop(seconds, rate)`; uses Odoo's own `application_name` so the application table of the Activity page is exercised realistically |
| `api.ts` | pglens API ground truth | authenticated `get(path)`; `series(metric, from, to, step)`; `activity()`; `findings()` — used to cross-check UI ↔ API ↔ PostgreSQL (three-way) |
| `observe.ts` | UI readers | `chartTable(page, title)` reads the sr-only data table of a chart (values, null count, completeness); `tableRows(page, name)`; `tile(page, label)`; `pager(page, name)`; `consoleGuard(page)` collects `console.error`, `pageerror`, failed/4xx/5xx requests and fails the test in `afterEach` unless the test whitelists a specific expected one |
| `budget.ts` | stimulus→response time budgets | one table of timeouts derived from the sampling intervals (below), used by `expect.poll(...,{timeout})` |

Response budgets (end-to-end = stimulus → visible in the UI, includes agent interval + ingest + UI refresh): activity/locks 10 s sample → **≤ 45 s**; `database_stats` 30 s → **≤ 90 s**; `stat_statements` 60 s → **≤ 150 s**; readiness items derived from an hourly check (`settings`) → **≤ 660 s** (600 s first-run cap after an agent restart + run time + 30 s cache), derived from flags or the environment → **≤ 90 s** (2 host ticks + 30 s cache); 15-min checks (`database_size`, `fk_indexes`, `function_security`) → **≤ 150 s after an agent restart** (120 s first-run cap D22a + run time + 30 s cache; relies on 13.1's immediate post-jitter scrape); hourly checks (`table_columns`, `extensions`) → **≤ 660 s after an agent restart**; a test that depends on either class restarts the agent after its stimulus and counts the restart in `n * BUDGET.serviceRestart`; tables/indexes 5 min → **≤ 8 min**; ASH 1 s sampling, 10 s flush → **≤ 45 s**; host 30 s → **≤ 90 s**; findings → as measured in 0.4 (advisor cadence) + 50 % until 11.4; from 11.4 the dev stack sets `PGLENS_ADVISOR_INTERVAL=60s` and `BUDGET.findings = 90_000` (60 s cycle + 30 s cache/refresh); `serviceRestart` (container restart until `/healthz` and the first agent heartbeat) → **120 s**. A budget is a property of the system, written once in `budget.ts`; a test never widens its own timeout.

## 4. Test classes and tags

| Tag | Class | Rule |
|-----|-------|------|
| `@smoke` | route sweep: every route of `fullhd_routes.ts` loads, no console/network errors, axe clean, data present | read-only, parallel-safe |
| `@indicators` | **stimulus → indicator** movement (below) | uses `pg.ts`/`odoo.ts` stimulus; each test has a *control* (no stimulus → indicator stays within noise) and a *sabotage check* run once and recorded (stimulus disabled → the test must fail), proving the assertion can fail |
| `@fullhd` | `VIS-FHD-*` at 1920×1080 and 1920×950 | structural scrollbar assertions (I-13) |
| `@lifecycle` `@destructive` | stop/start/restart/rebuild resilience | serial, guarded (section 2) |
| `@slow` | needs an observation window (unused-index verdicts, 1 h windows) | run at 6.2/6.4 only |
| `@visual` | screenshots for review | produces files, asserts non-blank canvas |

Playwright config (`web/playwright.config.ts`): the existing `chromium` project stays for the legacy specs (see 0.4); new projects `harness` (node-only), `desktop-fullhd` (1920×1080), `desktop-maximized` (1920×950), `laptop` (1440×900), `tablet` (768×1024), `phone` (390×844); the global `workers: 1` and `retries` stay (legacy specs), and every `@indicators`/`@lifecycle` spec sets `retries: 0` per describe block (a retry hides a defect; flakiness is fixed, not retried); each QA spec calls `test.setTimeout(<sum of the budgets the test waits for in sequence (appear, clear, control-run absence, sabotage-run persistence)> + n * BUDGET.serviceRestart + 60_000)` with the budgets from `budget.ts`, n = the number of service stops/restarts the test performs, and the arguments are written in the unit's e2e line (the global 30 s timeout stays for legacy specs); every other live spec in `web/e2e/console_visual.spec.ts` (and any non-legacy spec outside `web/e2e/qa/`) whose test can run longer than 25 s — a stimulus, a restart wait or a polling budget — calls `test.setTimeout(liveTimeout(stimulusMs, waitMs))` (`liveTimeout` = `stimulusMs + waitMs + 60_000`, exported by `web/e2e/visual_helpers.ts`, 0.2): VIS-016 `liveTimeout(420_000, 3 * 45_000)` (its own `rpc_load.py --seconds 360 --warmup 60` plus three viewport waits), COV-E2E-001 `liveTimeout(0, 900_000)` (waits up to 15 minutes for the matrix), any `expect.poll` with `timeout` above 25 s counts as `waitMs`; a test that iterates routes, viewports, tabs or hover targets counts `items * 30_000` as `waitMs` (items computed from the registry array, e.g. `FULLHD_ROUTES.length * 2`); a test with sequential waits sums them and adds `BUDGET.serviceRestart` per service stop/restart; VISTMO-001 (0.2, run inside VIS-000) asserts the arithmetic, and a unit that adds a live spec declares its `liveTimeout` arguments in its e2e line (a spec that iterates nothing and waits ≤ 25 s in total may write `timeout: default 30 s (≤ 25 s)` instead); every G-VIS/G-QA command passes `--project=<name>`; `trace: 'retain-on-failure'`, `video: 'retain-on-failure'`, `screenshot: 'only-on-failure'`; `expect.timeout` 10 s for static assertions, polling budgets from `budget.ts` for movement.

## 7. Accuracy rules (anti-bug)

1. Every assertion reads at least two independent sources when both exist: UI value, pglens API value, PostgreSQL truth.
2. No fixed sleeps. Polling with deadline from `budget.ts`; the failure message prints expected, last seen, source and timestamps.
3. Each test is isolated and idempotent: unique run tag, cleanup in finalizers, safe to rerun, order-independent (`--shuffle` safe) except explicit serial lifecycle describes.
4. Controls and sabotage: every `@indicators` test has a no-stimulus control and one recorded sabotage run (the test fails when the stimulus is withheld) — evidence in STATE §7.
5. Tolerances are written next to the assertion with their reason; never widened to pass.
6. Console errors, page errors, failed requests and non-whitelisted 4xx/5xx fail the test (`consoleGuard`).
7. Every spec lists, in its header comment, the unit IDs and requirement IDs it proves; `QA-TRACE-001` (Playwright project `harness`, `web/e2e/qa/traceability.spec.ts`, node-only) checks that every REQ row of the overview register has in its Proof column either at least one test-ID token (`<FAMILY>-<NNN>` or a `<FAMILY>-*` prefix) that resolves in **test sources only** — never in the plan's phase files: the literal ID/prefix as a string literal (a test title or `describe` name; comment-only matches do not count, and `web/e2e/qa/traceability*` itself is excluded) in `web/e2e/**/*.ts`, `web/src/**/*.test.*`, `test/**`, or in `**/*_test.go` the Go name by the hyphen-drop rule (`INT-RO-001` → `func TestINTRO001`, prefix `IDXE-INT-*` → `func TestIDXEINT…`) — or the literal marker `Exempt (manual evidence)`; `Exempt (manual evidence)` is accepted only for the REQ rows 01, 02, 03, 17, 18, 22, 23, 24 and 25 (environment/meta facts; any other row carrying it fails); REQ-21, whose unit runs after 6.4, is deferred in the 6.4 run through env `PGLENS_TRACE_DEFER=REQ-21` and checked in the 8.2 and final runs with it empty (REQ-20's `INT-RO-001` already resolves to `TestINTRO001`, so it needs no deferral).
8. Determinism of data: tests never depend on seed row counts except through ground-truth reads; they do not modify Odoo business data (only `qa_tmp` and an Odoo test partner category `QA`, removed afterwards).
9. Artifacts: HTML + JSON reports and screenshots under `test/e2e/_artifacts/ui/`; discovery counts (`playwright test --list | wc -l` per `-g`) recorded in STATE §7; a gate with zero discovered tests is a failure.
10. Live run environment: every live command exports from the stack `.env` (values never printed) `PGLENS_UI_BASE_URL=http://127.0.0.1:9090`, `PGLENS_UI_PASSWORD` and `PGLENS_BOOTSTRAP_TOKEN` (the `api` fixture throws without it), plus the guards a spec needs (`PGLENS_QA_ALLOW_STIMULUS`, `PGLENS_QA_ALLOW_LIFECYCLE`). Every non-legacy Playwright command names `--project` and selects tests with `-g '<ID or @tag>'` across the project's specs (no spec path in the gate, so a spec's file name never makes discovery zero); a unit may add a spec path only when it says so.
11. Failure triage: a failed live test is reproduced by hand against the API first; a real defect gets a regression test at the lowest layer that can catch it (Go/vitest) **and** stays covered live.
