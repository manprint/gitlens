# Phase 4 — Missing-index suggestions

Intent: the Index analysis page has a Suggestions tab that proposes missing indexes from the statements that actually cost the most time, ranked by weight, with an upper bound for the read benefit, an estimated size, the write overhead and a copy-ready `CREATE INDEX CONCURRENTLY` statement; an indexed access path is never suggested.

## Local design context
Plan revision: 1.
- D8: heuristic, dependency-free SQL analysis in Go package `internal/indexadvice` (pure functions, no database, no I/O); data comes from facts and metrics the server already stores: `query_texts(tenant_id, cluster_id, datname, queryid, pg_major, query_text)` (normalised statements, `$n` parameters, no literals), `metrics_statements` (per-second rates `calls_rate`, `exec_time_rate_ms`, `rows_rate`, `shared_blks_read_rate`, `wal_bytes_rate`; one row per `(instance, datname, queryid, ts)`), fact `index_def` (`pg_get_indexdef` text, key `schema.index`, labels carry table and database — see `internal/check/index_stats.go:177`), fact `table_columns` (JSON array per table: `name, attnum, type, typlen, notnull, n_distinct, null_frac, avg_width`; `internal/check/table_columns.go`), and `metrics_tables` (`n_live_tup`, `reltuples`, `relpages`, `total_bytes`, `seq_scan`, `idx_scan`, `n_tup_ins/upd/del/hot_upd` rates).
- Confidence and selectivity (D8): at Tier 0 (`n_distinct`/`null_frac` absent because `table_columns` statistics are unreadable) a suggestion's confidence is capped at `low` and carries the flag `selectivity_unknown`; with statistics the candidate key orders equality columns most selective first.
- Extractor contract (`Parse(sql string) Analysis`): a hand-written tokenizer (single quotes with `''`, double-quoted identifiers, dollar quoting, `--` and `/* */` comments, `$n` parameters, operators `= <> != < <= > >= ~~ !~~ ::`), then a clause scanner over SELECT/WITH/UPDATE/DELETE/INSERT…SELECT: tables with aliases from `FROM`, `JOIN`, `UPDATE`, `DELETE FROM`; WHERE/ON split at top-level `AND` (parenthesis depth 0); predicates of shape `[alias.]column <op> <expr>` with kinds `eq` (`=`, `IN (…)`, `= ANY(…)`), `range` (`< <= > >= BETWEEN`), `like_prefix` (`LIKE`/`ILIKE` against a literal not starting with `%`; a `$n` pattern is `like_unknown` and ignored), `isnull`; `ORDER BY` columns with direction (+ whether `LIMIT` exists); top-level `OR` groups, columns wrapped in a function or cast (`lower(col)`, `col::text`), unresolved aliases and statements it cannot tokenise are **skipped and counted by reason** (`or_group`, `expression`, `unresolved_alias`, `parse_error`, `unsupported_statement`, `catalog` — every relation of the statement is in `pg_catalog`/`information_schema`, nothing the user can index) — never guessed (I-5). Sub-selects in parentheses and CTEs are analysed as separate scopes with their own alias map. Output: `Analysis{Tables []TableRef{Schema, Name, Alias}, Predicates []Predicate{Table, Column, Kind, Dir}, Skipped []SkipReason}`.
- Candidate rules (`Suggest`): per statement and table: key = equality columns ordered by descending selectivity (`n_distinct` > 0 is a distinct count, < 0 is a fraction of rows; unknown ranks last), then **one** range / `like_prefix` / ORDER BY column last; at most 4 columns; a column of a type that cannot be btree-indexed (json, xml, point) is dropped with a note. Skip a table with `n_live_tup < 1000` (note `small_table`). **Covered** when an existing index (parsed from `index_def`: columns, `DESC`, `WHERE` partial predicate present → partial indexes cover only if the statement text contains the predicate text; `INCLUDE` columns never cover) has the candidate's key as a prefix, or its first key column equals the candidate's first equality column and the candidate has a single column. A candidate whose key is a prefix of another candidate on the same table merges into the longer one. Merged candidates sum the statements' `exec_time_rate_ms` and `calls_rate` over the window.
- Scoring (all labelled estimates, I-5): `weight_pct` = candidate's summed `exec_time_rate_ms` / summed `exec_time_rate_ms` of **all** statements of the database in the window × 100; `read_cost_ms_per_s` = the summed rate itself, shown as "upper bound of the time these statements spend today" (an index cannot remove more than all of it); `est_size_bytes` = `reltuples × (Σ width + 8 + 4) × 1.15` where `width` = `avg_width` when present, else `typlen` when > 0, else 32 (variable-length default, note `width_assumed`); `write` = table `n_tup_ins`, `n_tup_upd`, `n_tup_del` rates and `hot_update_ratio` = `n_tup_hot_upd / n_tup_upd`; `read_write_ratio` = `calls_rate / max(n_tup_ins + (n_tup_upd − n_tup_hot_upd) + n_tup_del, 0.001)` (the denominator counts only the row changes that must touch the indexes: HOT updates do not); `verdict`: `strong` ratio ≥ 10, `moderate` ≥ 1, `write_heavy` < 1 (documented heuristic constants, shown in the UI help); `selectivity` label from the first key column's `n_distinct` (`high` ≥ 1000 distinct or fraction ≤ -0.1, `low` ≤ 20 distinct, `medium` otherwise, `unknown` without statistics — a `low` first column lowers the verdict one step and adds the note `low_selectivity`).
- `create_statement` = `CREATE INDEX CONCURRENTLY idx_<table>_<cols> ON <schema>.<table> (<col> [DESC], …);` with identifiers quoted by `quoteIdent` (double any `"`, quote when not `[a-z_][a-z0-9_]*`), name truncated to 63 bytes with a stable 6-hex hash suffix; **pglens never executes it** (I-2).
- Ranking: `weight_pct` descending, ties by table then columns; default `limit` 20, max 100; window default 24 h (`1h`…`7d`).
- Endpoint contract (`getIndexSuggestions`): `GET /api/v1/instances/{id}/index-suggestions?window=24h&limit=20&database=<name>` → `{instance_id, generated_at, window_seconds, estimates_note, coverage:{statements_considered, statements_analysed, skipped:{reason:count}}, suggestions:[{id, database, schema, table, columns:[{name, desc}], create_statement, weight_pct, read_cost_ms_per_s, calls_rate, statements:[{queryid, share_pct, query_text (max 400 chars)}], overlapping_indexes:[name], selectivity:{column, n_distinct, label}, est_size_bytes, write:{insert_rate, update_rate, delete_rate, hot_update_ratio}, read_write_ratio, verdict, notes:[…]}]}`; `id` = first 12 hex of sha256(database|schema|table|columns). Errors: 400 bad `window`/`limit`, 404 unknown instance; an instance without `stat_statements` data returns an empty list with `coverage.statements_considered = 0` and a `notes` entry (the UI shows the readiness hint, 14.2).
- Golden corpus: `internal/indexadvice/testdata/odoo_corpus.json` (statements exported from the live stack's `query_texts`, includes aliases such as `"res_partner"."name"`, `ORDER BY … LIMIT`, `IN (…)`, joins, subselects, CTEs) with the expected `Analysis` per entry, reviewed by the `advisor`.
- I-3, I-5, I-6, I-7, I-9 apply; I-13 (Suggestions tab registered in `fullhd_routes.ts`).
