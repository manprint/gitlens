# Phase 16 — Locks and activity: session origin, richer sessions, per-application counts on by default

Intent: the Locks and activity page separates the sessions opened by pglens from the sessions opened by the application (two tables, counted separately), shows full connection and active-query information for every session, summarises connections by origin/application/user/client/database/state, and `checks.activity.by_application` is on by default.
Prerequisites: 9.1 (table controls), 15.1 (density tokens), 17.1 (captions), 14.1 (`agent_flags` fact is extended here with the new flags). Order: after phase 14 (overview execution order).
Phase closure: P16; review by `advisor`.

## Local design context
Plan revision: 1.
- D27 and D28 (overview) are the contracts; assumptions A3 (raw session text opt-in).
- Classifier (D27): new stdlib-only leaf package `internal/sessionorigin`: `Origin(applicationName, usename, monitorRole string) string` returns `"pglens"` when `IsPglensApplication(applicationName)` (`== "pglens"` or prefix `"pglens/"` or `"pglens-agent/"`, list exported as `Prefixes`), or when `monitorRole != ""` and `usename == monitorRole`; otherwise `"application"`. Pure, exhaustive table tests. Three callers use it: the agent `activity` check (`pg_connections_by_origin`), the signal guard (`internal/agent/exec_signal.go`: `isPglensApplication` is deleted, the guard's SQL predicate is rendered from `Prefixes`), and the server (`api_locks.go` classifies each sampled session). The agent names its own sessions `pglens/check` (`cmd/pglens-agent/main.go`), `pglens/ash`, `pglens/shared` (`internal/agent/conn.go`), `pglens/<datname>` (`internal/agent/conn.go`); the agent's `activity` check never receives the monitoring role: it counts `pglens` sessions in SQL as `application_name` matching the predicate rendered from `Prefixes` **or** `usename = current_user` (as `exec_signal.go` already does for the guard), so targets with different DSN users stay correct; only the server needs the role, taken from the `role` label of the latest `monitoring_role` fact (16.2).
- Agent metrics (additive, bounded top-10 + `other` through the existing helper `boundedActivityMetrics`): `pg_connections_by_origin{origin}` (always on, both origins always emitted, zero included, over the same `client backend` filter as the other connection metrics), `pg_connections_by_user{usename}`, `pg_connections_by_client{client_addr}` (a NULL `client_addr`, i.e. a Unix-socket client, is keyed `local`); `pg_connections_by_application` unchanged (now default on).
- Config: `internal/agent/config.go` `ByApplication` becomes `*bool` (nil → true; explicit `false` honoured); the check's own default is true; `deploy/agent.example.yaml` (comment and value), `README.md` (the `by_application` row), `QUICK_START.md` if it mentions it, and `docs/` say `true`. New key `checks.locks.session_query_text` (`*bool`, default false) for raw text (D28d); both keys are published in the `agent_flags` fact (14.1).
- Session sample (`lockNode`, cap 100, `internal/check/locks.go`) gains: `origin` is **not** stored by the agent (the server classifies from fields + the instance's monitoring role, one Go function), `query_age` (seconds since `query_start`), `backend_xid_age`, `backend_xmin_age` (ages in transactions, never ids), `query_id` (PG ≥ 14, string of the bigint; omitted when NULL/0), `leader_pid` (parallel workers), `backend_type` filter stays `client backend`, `query_start`. Raw `query` on session rows only when `session_query_text: true`, always passed through the existing `redactQueryText`/`withheldQuery` handling (`internal/check/query_redact.go`, used by `locks.go`) (a text that cannot be shown is replaced by `withheldQuery`, never cut and sent; I-10). Existing JSON fields keep their names (I-7).
- Server API: the session list handler in `internal/server/api_locks.go` (verify the handler name in S1) adds per session `origin`, `query_text` + `query_text_source` (`'normalised'` resolved by `query_id` from `query_texts`; `'raw'` when the agent sent text; omitted when unknown), and a top-level `connections` summary `{by_application_enabled, by_origin, by_application, by_user, by_client, by_database, by_state}` each `[{key, count}]` sorted by count then key, derived from the **same sample** (so the tables and the summary cannot disagree) plus the totals from the activity metrics. The activity metrics query list in `handleActivity` gains the three new metric names. OpenAPI/generated types/fixtures/docs updated (I-6).
- UI (`web/src/features/locks/ActivitySection.tsx`, `web/src/lib/locks.ts`, `web/src/lib/activity.ts`): the "Active sessions" `<ul>` of cards becomes two `DataTable`s with the shared controls — **Application sessions** (primary, first) and **pglens monitoring sessions** (second, caption: "Connections opened by pglens itself to collect these metrics; they are not your workload"); the connection tile shows `application N · pglens M` as one labelled sentence (D31); `BlockingTree` nodes carry an `app`/`pglens` badge; a **row detail** (expand, user action) shows every field: state, wait event type/event, transaction age, query age, state age, backend start, client address, application, user, database, backend xid/xmin ages, query id, `leader_pid`, normalised text (and raw text when present) with `CopyButton`, blocked-by / blocking relations, signal actions (existing `SignalActions`); a **connection summary** panel (tabs By origin / application / user / client / database / state, each a small table with counts and a share bar); the "Per-application activity counts" callout only appears when `connections.by_application_enabled === false` (explicit opt-out) and then names the key.
- Counts consistency (I-15): the sum of the two tables' rows plus truncated remainder equals `connections.by_origin`; `application + pglens` equals the client backends of `pg_stat_activity` minus the sampling backend (ground truth in the live test).
