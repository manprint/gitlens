# Phase 14 — Monitoring readiness: say what prevents FULL monitoring and how to enable it

Intent: for every monitored server the console states whether monitoring is `full` or `partial`; every gap is a warning that names the features it costs, the evidence found, and ordered fixes — a console control when one exists, otherwise copy-ready SQL, PostgreSQL configuration, `agent.yaml` or host-mount steps.

## Local design context
Plan revision: 1.
- D25 (overview) is the contract. Evaluator is pure: `internal/readiness.Evaluate(Input) Report`, no I/O, no clock reads except `Input.Now`.
- `Input` (all values the server already stores, assembled by `internal/server/readiness.go`): `Instance{ID, PGVersion, IsStandby, PermTier, MonitoringRole}`, `Settings map[string]string` and `SettingSources map[string]string` (latest `setting` facts incl. `source` when the fact carries it — verify in 14.1 S1; `pg_settings.source` such as `command line`, `configuration file`, `user`): `shared_preload_libraries`, `compute_query_id`, `track_io_timing`, `track_activity_query_size`, `pg_stat_statements.track`), `Extensions map[string][]string` (`extension` facts, keyed by database: the check is per database and hourly), `Role{HasPgMonitor, HasReadAllStats *bool}` (labels `has_pg_monitor` and `has_read_all_stats` that 14.1 S2 adds, additively, to the existing `monitoring_role` fact, from `pg_has_role(current_user, …, 'MEMBER')` — today that fact carries only the labels `role` and `read_only_default`, and its membership list deliberately excludes `pg_monitor`/`pg_read_all_stats`; an older agent omits the labels → nil → the item is omitted), `Skips []CheckSkip{Check, Reason}` (`check_skip` facts), `FailingChecks []string` (latest `check_failing` self-metric > 0), `HostSeries{HasDiskTotal, HasCPU}` (presence of `host_disk_*`, `host_cpu_*` series in the window), `Flags AgentFlags{CommandsEnabled, AllowSignal, ByApplication, SessionQueryText, HostLocal, DataDirectoryReadable *bool}` (nil = unknown → the item is omitted, never guessed), `DatabasesDiscovered, DatabasesBudget int`, `NotificationChannels int` (configured count, 11.5a), `Now time.Time`.
- `agent_flags` is a new **additive fact kind** (registry `internal/wire/factkinds.go`): the agent emits `{commands_enabled, allow_signal, by_application, session_query_text, host_local, data_directory_readable}` booleans per instance (target) (no secrets, no paths) at startup (config-derived flags; `data_directory_readable` stays nil until the first host collection), after a host collection whose `data_directory_readable` differs from the last emitted value, on config change and hourly; a server that does not know the kind drops it and counts it under ingest-rejected `invalid_fact` (`Fact.Validate()` → `unknown fact kind`, `internal/server/pipeline.go` ~515; the wire-compatibility test asserts the counter). Older agents → flags nil → items omitted.
- `Report`: `{instance_id, level: 'full'|'partial', generated_at, counts: {warning, info}, items: [Item]}`; `Item`: `{id, severity: 'warning'|'info', title, summary, impact: string[], evidence: string, fixes: [Fix]}`; `Fix`: `{channel: 'console'|'agent_config'|'sql'|'postgres_config'|'host', title, steps: string[], snippet?: string, requires_restart: bool, route?: string}`. `level = full` iff zero warnings. Items sorted: warnings first (by id), then infos.
- Rules (stable ids; table in `internal/readiness/rules.go`, each rule a struct `{ID, Severity, Applies(Input) bool, Build(Input) Item}`):

  | ID | Severity | Fires when | Impact (features lost) | Fixes (channel) |
  |----|----------|-----------|------------------------|-----------------|
  | RDY-EXT-01 | warning | no monitored database lists `pg_stat_statements` in `Extensions`, or `shared_preload_libraries` lacks it | Slowest queries, statement charts, index suggestions | `postgres_config`: `shared_preload_libraries = 'pg_stat_statements'` + restart; `sql`: `CREATE EXTENSION pg_stat_statements;` in each monitored database |
  | RDY-SET-01 | warning | PG ≥ 14 and `compute_query_id = off` | session ↔ statement link, normalised text for active sessions | `postgres_config`: `compute_query_id = auto` (or `on`), reload |
  | RDY-SET-02 | warning | `track_io_timing = off` | I/O time charts, per-statement I/O time | `sql`: `ALTER SYSTEM SET track_io_timing = on; SELECT pg_reload_conf();` (no restart) when the setting source is `configuration file`/`default`; when the source is `command line` the fix is `postgres_config`: change the server start command (for the dev stack, the compose `command:` line), restart required |
  | RDY-ROLE-01 | warning | `Role.HasPgMonitor == false` or `Role.HasReadAllStats == false` (nil → the item is omitted) | statistics of other users' sessions and statements, settings | `sql`: `GRANT pg_monitor TO <monitoring_role>;` or run `deploy/sql/monitoring_user.sql` as documented in `deploy/sql/README.md` |
  | RDY-HOST-01 | warning | the target is `host_local` (`Flags.HostLocal == true`) and (`Flags.DataDirectoryReadable == false`, or `Flags.DataDirectoryReadable == nil` and no `host_disk_*` sample in the last 10 minutes) | Host filesystem total/free charts | `host`: mount the PostgreSQL data directory read-only into the agent container at the same path (`compose` snippet), restart agent |
  | RDY-CHK-01 | warning | a check is in `FailingChecks` | the failing check's data | `host`/`console`: open Findings → agent log; per-check hint text; evidence names the check |
  | RDY-CHK-02 | warning | `Skips` has a reason other than tier/version (e.g. missing extension, missing privilege) | the skipped check's data | per reason (same fixes as the matching rule above; unknown reason → generic) |
  | RDY-ACT-01 | warning | `Flags.ByApplication == false` | Per-application connection counts | `agent_config`: `checks.activity.by_application: true`, restart agent |
  | RDY-DB-01 | warning | `DatabasesDiscovered > DatabasesBudget` | databases beyond the budget are not analysed | `agent_config`: raise the per-target database budget (exact key verified in 14.1 S1 from `internal/agent/config.go`), restart agent |
  | RDY-NOTIF-01 | warning | `NotificationChannels == 0` | alert delivery (Slack, Google Chat, webhook) | `console`: Settings → Notifications (`route: /settings?tab=notifications`); `host`: environment variable instructions |
  | RDY-T2-01 | info | `PermTier < T2` | cancel/terminate of other sessions from the console (also needs `allow_signal`; Tier 2 is only the `pg_signal_backend` grant) | `sql`: `monitoring_user.sql -v role=<monitoring_role> -v tier1=1 -v tier2=1` (invocation per `deploy/sql/README.md`) |
  | RDY-EXT-02 | info | `pgstattuple` is not in `Extensions` of a monitored database | exact bloat on demand (the `pgstattuple` command) | `sql`: `CREATE EXTENSION pgstattuple;` in that database, run by a DBA (pglens never creates extensions) |
  | RDY-CMD-01 | info | `Flags.CommandsEnabled == false` | on-demand EXPLAIN, command audit | `agent_config`: `commands.enabled: true` |
  | RDY-SIG-01 | info | `Flags.AllowSignal == false` (per target) | cancel/terminate buttons | `agent_config`: `allow_signal: true` (needs T2) — marked "deliberately off by default" |
  | RDY-SESS-01 | info | `Flags.SessionQueryText == false` | raw text of active sessions (normalised text is still shown) | `agent_config`: `checks.locks.session_query_text: true` — warns that literals may be sensitive |
  | RDY-SET-03 | info | `track_activity_query_size < 4096` | long statements are truncated in activity | `postgres_config`: `track_activity_query_size = 4096`, restart |

  Snippets use `Input.Instance.MonitoringRole` (or the literal `<monitoring_role>` when unknown), never a password or token.
