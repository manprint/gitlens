## 4. Findings

### V001-F1 — full E2E exit status is not directly verifiable

- **Status:** `FIXED`
- **Severity:** `MINOR`
- **Category:** stale-state / untested gate
- **Where:** `docs/plans/002_plan-AnalysisBackend/STATE.md` §7 row
  `V001-e2e-full`; prior closure row `phase10.5-e2e-full`; deviation D-058.
- **Plan reference:** `phase_11.md` §10.5, final gate list and done criterion
  (`make test-e2e-full` is required and the gate must be green).
- **Expected:** a durable record proving that `make test-e2e-full` returned
  exit 0, with the process/container cleanup checks complete.
- **Actual:** the long runner continued to completion and no failure markers,
  residual E2E process, or pglens container was observed, but the surrounding
  RPC timed out before the wrapper's final exit line was captured.
- **Impact:** the state table currently describes completion evidence, not a
  directly proven green exit status for the gate on this audit run.
- **Correction:** reopen phase 10.5's final-gate verification; run
  `make test-e2e-full` through a persistent wrapper that records the command
  output and `wait` exit code in
  `docs/plans/002_plan-AnalysisBackend/verify/evidence/V001-e2e-full.log`;
  require exit 0, no failure markers, and no residual process/container; then
  update `STATE.md` §7, §9 and §11 plus this report/index. The finding closes
  only when the durable log and exit 0 are present.
- **Fixed:** 2026-08-31 — `test/e2e/_artifacts/e2e-full-20260831T040622Z.log`
  records `RESIDUAL_CONTAINERS=0`, `RESIDUAL_NETWORKS=0`, and the literal line
  `EXIT_STATUS=0 FINISHED_AT=2026-08-31T05:12:01Z COMMAND=make test-e2e-full`
  after 3939s (65m39s).

- **Plan reference:** `phase_11.md` §10.5 closure requirement that every
  planned `T-*`, `INT-*` and `SYS-*` ID be resolved, plus the state-board
  traceability invariant.

  tracked extensions.

  but the stronger repository-wide sentence is false for legacy/auxiliary IDs,
  including `INT-API-002`, `INT-CONN-001`, `INT-REPL-001`, `INT-WL-002`,
  `SYS-AGENT-001`, `SYS-DB-001` and `SYS-TOPO-001`.
- **Impact:** future auditors can mistake the plan board for a complete
  repository test registry, and legacy ownership is not discoverable from this
  state file.
- **Correction:** update `STATE.md` §11 in one correction unit: either append
  all missing concrete source IDs with their owning plan/status, or narrow the
  invariant to “all plan-002 planned IDs and explicitly tracked extensions”
  and link legacy IDs to their owning plan's state. Re-run the source-vs-state
  check under the chosen rule and record a zero unexpected-difference result.
- **Fixed:** 2026-08-31 — `scripts/id_audit.sh` and its Go test are present;
